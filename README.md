# pi-sandbox

**简体中文** | [English](README.en.md)

> 面向 Pi coding agent 的可配置权限审批链与受控执行扩展。

## 项目简介

Pi agent 的一次工具调用可能读取或修改文件、运行 Shell 命令、启动子进程、访问网络，也可能经过 MCP 服务调用外部工具。只根据工具名称放行或拒绝，很难判断这次调用的真实目标，也无法保证实际执行内容仍与审批时相同。

`pi-sandbox` 在 Pi 工具调用前运行可配置的审批链，再将获准范围绑定到实际执行。审批回答“这项操作是否可以继续”；沙箱执行器回答“获准的进程实际上能访问什么”。两者配合，避免把模型判断或用户确认直接当作操作系统边界。

## 主要功能

### 可配置审批链

审批链把一次工具调用拆成有顺序、各司其职的检查阶段。内置阶段包括结构分析、调用者与工具身份识别、规则求值、访问目标评估和模式裁决；Bash、PowerShell 与外部命令分析可按配置启用。LLM 审批、Decision 审批和人工确认也可按配置启用。

```text
工具调用
  → 结构与目标分析
  → 身份和规则检查
  → 文件、网络、进程等访问评估
  → 可选的 Shell 分析与模型审批
  → 对仍需确认的请求进行人工审批
  → 生成 allow / ask / deny 结果
```

#### 为什么需要审批链

例如，`bash` 工具调用可能在同一条命令中读取文件、修改配置、启动进程并访问网络。只按 `bash` 这个工具名做一次 allow/deny，无法表达每项操作的目标，也难以把写文件和网络访问分别交给对应规则处理。

审批链把这些问题分层处理：先确认谁在调用什么，再识别操作目标并匹配策略，最后只把尚未解决的请求交给模型或用户。每个节点都基于同一调用的证据工作；拒绝不能被后续 allow 覆盖，节点错误或超时也不会自动放行。

#### 审批结果

- `allow`：当前操作在获准范围内继续进入受控执行。
- `ask`：需要额外审批；在 Pi 中由人工确认节点处理未决请求。
- `deny`：阻止当前操作，后续节点不能把拒绝改成允许。

#### 审批链的设计目标

- **分开处理不同证据。** 规则节点执行明确策略；分析节点识别工具调用涉及的路径、命令和访问目标；模型或用户处理仍需判断的请求。
- **让决定可解释。** 每个节点针对具体调用证据产生结果，便于追踪哪条规则或哪一步评估影响了决定。
- **保持拒绝优先。** 后续节点不能把已有的拒绝改成允许。节点故障或超时不会自动放行；未解决的请求继续询问或拒绝。
- **支持按场景选择模式。** `/permission` 可查看或切换审批模式；`/permission settings` 可配置审批节点和模型。

### 沙箱受控执行

审批通过并不意味着任意执行。`pi-sandbox` 接管 Pi 内置工具和受管理的 MCP 工具，并在实际执行前检查调用身份、参数、策略版本和获准访问范围是否仍然一致。若调用内容改变或授权依据失效，执行不会沿用旧批准。

受控执行可以限制：

- **文件系统：** 按读、写授权授予具体文件或目录访问；写入范围不能由读取授权扩大。
- **进程：** 按策略决定是否允许启动子进程，并由平台后端执行对应隔离。
- **网络：** Shell 使用顶层网络范围。`none` 不允许网络；`allowlist` 只允许 `allow` 列表中的目标，并通过受控出口代理；`all` 允许全部网络目标。目标省略 `port` 时仅允许 HTTP 80 和 HTTPS 443；使用 `port: "any"` 可允许任意端口。
- **MCP：** 默认在宿主运行，保留调用审批与生命周期管理。实验性 `experimental.mcpSandbox` 开启后，stdio 和 HTTP MCP 才与内置工具复用当前会话沙箱及有效的 `execution.network`；stdio 通过受控后端启动，受限网络使用临时租约，HTTP 请求检查同一网络范围。
- **Codemode：** 嵌套工具继承外层调用的一次批准，不重复审批；每次嵌套执行仍须经过受控绑定和沙箱。

平台和传输类型支持的能力不同。后端缺失、不支持请求的限制，或无法证明执行范围时，系统会拒绝执行，不静默退回到无约束运行。

### 执行边界

沙箱保护的是 `pi-sandbox` 接管的内置工具执行路径，以及显式开启实验性 MCP 沙箱后的 MCP 调用，不是整个 Pi 进程的全局隔离。默认在宿主运行的 MCP、没有接入这些受控路径的其他扩展或进程，不会因此自动受到沙箱限制。

## 安装与配置

发布后，在 Pi 中安装：

```sh
pi install npm:@sirzero/pi-sandbox
```

- Node.js `>=22.19.0`
- Pi 宿主依赖需满足本包 `peerDependencies` 声明
- 使用 `/permission` 切换模式，使用 `/permission settings` 配置审批节点和模型

实验性 MCP 沙箱默认关闭，MCP 直接在宿主运行。如需恢复后续开发中的沙箱路径，可在全局配置中显式开启：

```json
{
  "experimental": {
    "mcpSandbox": true
  }
}
```
